# IdeaLens 3페이지 시장성 보고서 재설계 브리프

## 목적

3페이지는 뉴스·기업 동향을 요약하는 화면이 아니라, 기획자와 사업 승인 담당자가 **어떤 초기 시장에 어떤 검증을 먼저 할지** 결정할 수 있는 검토 문서여야 한다. 현재 확인된 데이터가 빈약하면 그 한계를 숨기지 않으면서도, 다음에 확인할 고객·자료·성공 기준을 구체적으로 제시한다.

## 먼저 확인할 데이터 계약

화면을 바꾸기 전에 수집·검색·분석의 실데이터 경로를 확인한다.

- 자료별 제목, 출처/발행자, 발행일, URL, 인용 ID, 원문 또는 수집 발췌
- 자료 유형: 고객 검증, 구매·조달 신호, 공공 통계, 기업 주장, 보도자료, 산업 뉴스 등
- 자료의 직접성·신뢰도·최신성·아이디어 관련성
- 차원별 검색 결과와 결과 없음, 검색 실패, 관련성 판정 실패 상태
- 아이디어 초안 필드와 출처: 사용자 입력, 자료에서 추출, LLM 가설, 미확인
- 현재 MarketReport 스키마, 프롬프트, 보고서 Markdown 및 최종 보고서 연결 계약

인용 ID가 실제 자료와 연결되지 않거나, 기사 요약을 원문 사실로 과장하는 경로가 있으면 우선 수정한다. 수집되지 않은 자료를 LLM에게 보완하도록 지시해 사실처럼 쓰게 하지 않는다.

## 화면의 의사결정 질문

1. 첫 진입 고객은 누구이며, 사용자는 누구이고 구매 결정자와 예산 주체는 누구인가?
2. 어떤 업무 순간에 문제가 발생하며 현재 대안의 비용·시간·품질 영향은 무엇인가?
3. 고객이 지금 대안을 바꿀 이유가 있는가? 어떤 직접 근거가 있는가?
4. 첫 진입 시장을 좁힐 수 있는 사용 사례, 업종, 고객 규모 또는 설치 환경은 무엇인가?
5. 도입·조달·보안·규제·운영·연동에서 승인 또는 파일럿을 막을 장벽은 무엇인가?
6. 현재 근거로 결정할 수 있는 범위와 승인 전에 검증해야 할 가정은 무엇인가?

## 권장 화면 정보 구조

### 1. 사업 검토 요약

화면 첫 부분에 다음을 짧게 보여 준다.

- 시장 검토 상태: 직접 고객 검증 / 구매자 신호 / 간접 산업 신호 / 판단 보류
- 초기 진입 세그먼트와 선택 이유
- 지금 내릴 수 있는 결정: 고객 인터뷰 진행, 파일럿 범위 검토, 추가 자료 수집 등
- 판단 신뢰도 및 가장 큰 데이터 공백

검색 결과가 없다는 사실은 시장 수요가 없다는 의미로 표현하지 않는다.

### 2. 고객과 문제의 구매 구조

사용자, 실제 업무 담당자, 구매 결정자, 예산 주체를 분리한다. 각 항목에는 `자료에서 확인`, `자료 기반 해석`, `LLM 검증 전 가설`, `자료 없음` 상태를 붙인다.

- 업무 상황과 문제 발생 맥락
- 문제 빈도·영향(근거가 있을 때만 수치 표시)
- 현재 대안과 전환 계기
- 구매·조달 절차와 관련 부서
- 도입에 필요한 운영·보안·규제·연동 조건

### 3. 시장 진입 기회와 경쟁 대안

- 초기 세그먼트 1개를 우선 추천하고 선택 이유와 제외한 대안을 설명
- 직접 경쟁제품과 현재 업무 대안(수작업, 기존 설비, 외주 등)을 구분
- 제품의 차별점이 구매 이유가 될 가능성과 이를 확인할 근거를 제시
- 시장 규모(TAM/SAM/SOM)는 신뢰할 자료와 산출식이 있을 때만 표시
- 시장 규모·성장률·가격을 확인할 수 없다면 숫자를 생성하지 않고 필요한 데이터와 수집 방법을 제시

### 4. 수요 근거 패널

근거를 구매 의사에 가까운 정도로 분리한다.

- 직접 검증: 인터뷰, 설문, 파일럿, LOI, 실제 구매·조달 자료
- 구매자 신호: 예산·조달·구매 검토를 구체적으로 보여주는 자료
- 간접 산업 신호: 기업 도입 사례, 뉴스, 보도자료, 산업 동향
- 근거 없음 또는 미확인

각 주요 판단에는 실제 인용 ID를 표시하고, 클릭 또는 접기 영역에서 출처·발행일·발췌를 확인할 수 있게 한다. 간접 산업 신호를 고객의 구매 의사로 표현하지 않는다.

### 5. 사업 승인 전제와 검증 실험

최대 3개의 우선 검증 과제를 제안한다. 각 과제에는 다음을 포함한다.

- 검증할 가정
- 누구에게 확인할지(역할·세그먼트)
- 인터뷰·문서 조사·가격 테스트·현장 파일럿 등 방법
- 성공·실패 기준과 필요한 표본 또는 관찰값
- 결과에 따라 내릴 다음 결정
- 예상되는 비용·기간은 근거가 있으면 표시하고, 없으면 미확인으로 남김

## LLM 출력 계약과 근거 원칙

- LLM은 자료 요약자이자 초기 사업 검토자다. 검색 근거, 사용자 초안, 각 자료의 유형·날짜·신뢰도·직접성을 입력으로 받는다.
- 출력은 확인된 사실, 자료 기반 해석, 검증 전 가설, 미확인을 별도 필드로 분리한다.
- 가설은 근거/추론 이유, 가정, 검증 대상, 방법, 성공 기준을 포함한다.
- 인용은 입력으로 제공된 citation ID만 사용할 수 있고 서버에서 유효성을 검증한다.
- 근거가 없는 주장·수치·가격·시장 규모·전환율·구매 의향은 생성하지 않는다.
- 추정값은 원문 자료에서 확인 가능한 수치와 계산 입력이 있을 때만 허용한다. 출처 값·산식·단위·기준일을 함께 남긴다.
- 뉴스나 기업 자료만으로 수요를 `confirmed` 처리하지 않는다.
- 검색 실패, 자료 없음, 관련성 부족, 모델 응답 오류를 각각 구분한다.
- 시장 데이터가 부족할 때는 빈칸을 그럴듯한 내용으로 채우지 말고 결정 가능한 범위와 자료 수집 계획을 명시한다.

## 간결한 화면 우선순위

- 기본 화면은 결론, 초기 세그먼트, 근거 수준, 승인 전 확인 과제만 보여 준다.
- 자료별 전체 목록, 원문, 세부 차원 평가, 응답 메타데이터는 접힌 상세 영역으로 둔다.
- 모바일과 작은 화면에서도 결론 및 다음 행동을 먼저 읽을 수 있도록 한다.
- 4단계 최종 실행 검토에서는 이 보고서를 복사하지 않는다. 시장 판단의 핵심 근거와 미확인 가정만 전달한다.

## 수용 기준

- 사업 승인 담당자가 첫 화면에서 초기 고객, 구매 근거 수준, 주요 장벽, 다음 검증 행동을 빠르게 파악한다.
- 사실·해석·가설·자료 없음의 상태가 화면, 스키마, Markdown, 최종 보고서에서 유지된다.
- 인용 ID가 없는 시장 사실이 확정 정보처럼 렌더링되지 않는다.
- 뉴스·기업 자료만으로 직접 수요나 구매 의향을 확인했다고 표시하지 않는다.
- 검색 자료가 없을 때 수치나 시장 규모를 만들어 내지 않는다.
- 가설마다 검증 대상·방법·성공 기준이 있고, 검증 결과가 다음 사업 결정과 연결된다.
- 실제 API 호출 없이 가짜 응답으로 상태·인용·부분 실패 테스트를 수행할 수 있다.
