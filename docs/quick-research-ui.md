# 빠른 조사 UI — 참고 흐름과 구현

## 기준

사용자가 지정한 [타날리시스 빠른 조사 매뉴얼](https://tanalysis-1.gitbook.io/tanalysis-docs/prior-art-manual/flow1-quick)의 4단계 흐름과 실제 화면 배치를 기준으로 한다. 브랜드·이미지·문구를 복제하지 않고 입력과 확인, 후보 선정, 보고서의 작업 구조를 적용한다.

| 참고 구조 | IdeaLens 적용 |
|---|---|
| 큰 입력란 + 우측 최근 입력 | 명칭·내용, 템플릿, 세션 최근 입력 |
| 핵심 구성 확인 | 직접 수정, 위/아래 이동, 삭제·추가, 최대 7개 |
| 좌 구성 / 중 후보 / 우 선택 목록 | 구성 고정, 특허·시장 후보 탭, 공통 선택 목록 |
| 선택 문헌 + 본문 보고서 | 좌 선택 자료 / 우 요약·영역별 근거·연결 검토·메모·다운로드 |

왼쪽 단계 사이드바는 사용하지 않는다. 홈 로고를 누르면 첫 화면으로 돌아간다. 상단 1~4 버튼과 본문의 다음/이전 버튼으로 진행한다. 구성·질문을 확정하기 전에는 3단계, 자료 2건 선택 전에는 4단계를 열 수 없다. 완료한 단계는 자유롭게 다시 볼 수 있고 입력·선택·메모를 유지한다. 주요 진행은 필수 입력 → 유효한 구성 → 문헌 선택 → 보고서 순서로 제한한다.

## 특허·시장 두 조사 연결

공통 아이디어와 구성을 확정한 뒤 두 조사 결과를 각각 검토한다. UI에서는 조사 탭과 출처 유형을 나누되 하나의 선택 목록과 종합 보고서로 연결한다. 최소 2건이면 보고서를 열 수 있고 한 영역의 자료만 선택하면 반대 영역을 미확인으로 표시한다. 이 수량은 시연 UI 조건이며 분석의 충분성을 뜻하지 않는다.

실제 병렬 실행·상태 조회·재시도·분석은 백엔드 미연결이다. 통합 담당자와 공통 요청 ID·구성 ID, 특허/시장별 진행·완료·빈 결과·오류 상태, 근거 ID·원문·기업·시점 및 두 근거의 연결 가설을 합의해야 한다. 특허 관련성·시장 근거 품질을 같은 점수로 합치지 않는다.

## 동작과 경계

- AI 특징 추출은 미연결이다. 예시는 사전 작성한 구성이고 사용자 입력은 직접 구성한다.
- 정확한 예시 입력에만 가상 후보를 표시한다. 실제 검색·원문·도면·권리 상태는 미연결이다.
- 구성별 대응은 미검토로 표시하며 ◎/O/△/X나 정확도를 임의 생성하지 않는다.
- 문헌 상세를 읽고 추가/제외하며 보고서에는 선택 자료만 반영한다.
- 구성·입력을 다시 확정하거나 선택을 바꾸면 기존 보고서를 무효화한다.
- 시장 요구와 기술의 관계는 추가 검증 질문으로 제시한다. 실제 통합 분석 완료로 표시하지 않는다.
- 최근 입력·메모는 세션 메모리에만 보관한다. 영구 저장·회원 계정·팀 공동편집은 미구현이다.
- 기존 비용 계산 함수는 보존하지만 이번 화면의 주요 단계에서 제외했다. 보고서의 다음 검증 항목으로만 안내한다.

## 확인 순서

예시 불러오기 → 핵심 구성 확인하기 → 구성 수정·순서 이동 → 조사 시작 → 특허·시장 탭에서 각각 자료 추가 → 최소 2건으로 보고서 생성 → 선택 근거와 미확인 영역 확인 → 메모·다운로드.

직접 입력은 실검색 미연결 상태를 확인한다. 빈 구성·중복·최대 개수, 두 문헌 미만의 생성 제한, 자료 제외 시 보고서 무효화를 테스트한다.


## 질문별 연결 검토

2단계에서 핵심 구성 외에 검토 질문(최대 5개)과 도입 조건을 직접 편집한다. 아이디어 구조화와 실제 검색은 기존 백엔드 역할이며 이 화면의 질문이 자동 생성·검증됐다는 의미는 아니다.

3단계의 특허·시장 자료 선택과 ‘질문별 연결 검토’는 구분한다. 연결 기록은 아래 필드를 사용한다.

| 필드 | 내용 |
|---|---|
| question_id | 검토 질문의 안정 ID |
| component_ids | 관련 아이디어 구성 ID 목록 |
| market_ids / patent_ids | 선택한 각 영역의 근거 ID 목록 (여러 건 허용) |
| relation | 판단 보류 / 해결 방식 관련 / 도입 조건 충돌 가능 / 차별화 검토 / 사업 방향 관련 |
| reason | 사용자가 작성한 연결 이유·가설 |
| conditions | 환경·성능·기업·시점의 차이와 한계 |
| counter_ids / counter_reason | 반대·충돌 근거와 설명, 미조사 사항 |
| next_check | 추가 검증 과제 (필수) |

시장과 특허의 요약문 유사도를 관계 판정으로 사용하지 않는다. 사용 맥락·과제·구성·성능·도입 제약·근거 범위의 6개 기준을 보여준다. 뉴스나 기업 자료를 고객 구매 의사의 직접 검증으로 격상하지 않는다. ‘사업 방향 관련’은 실제 제품 적용 확인과 다르다.

질문별 양쪽 근거·관련 구성·이유가 있어도 **사용자 연결 가설 / 원문 검증 전**으로 표시한다. 한쪽 근거가 없거나 연결을 기록하지 않았거나 판단 보류를 선택하면 **통합 판단 보류**다. 질문에 유리한 근거뿐 아니라 반대 근거도 선택하고 보고서에 인용할 수 있다.

입력·구성·질문·도입 조건 수정 시 연결과 보고서 및 자료 선택을 초기화하고 2단계 재확정을 요구한다. 자료 선택 변경·연결 저장/제외 시 보고서를 무효화하며, 이미 연결된 자료가 제외되면 통합 상태를 다시 계산해 보류한다. 선택 자료의 인용·위치·대상·시점·버전은 보고서 스냅샷에 포함한다. 현재 예시의 시점·기업 식별·실제 URL은 미확인이며 값을 만들어 채우지 않는다.

4단계는 질문별 연결표, 양쪽 인용문, 조건 차이, 반대 근거와 다음 검증을 표시한다. Markdown 다운로드에도 같은 질문별 내용을 담는다.

백엔드 연결 전에는 검토 질문·구성 ID와 `MarketReport`/`PatentReport`의 근거를 함께 전달할 응답 계약이 필요하다. 이 UI 전용 연결 기록은 아직 팀의 공통 API 모델로 확정되지 않았다.
