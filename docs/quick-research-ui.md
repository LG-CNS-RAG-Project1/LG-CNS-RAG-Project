# 빠른 조사 UI — 아이디어 사업 검토 흐름

## 화면 흐름

| 단계 | 사용자 작업 | 주요 결과 |
|---|---|---|
| 1. 아이디어 입력·초안 확인 | 한두 문장 입력 후 전체 분석 시작. 누락 정보가 있으면 질문에 답하거나 미확인으로 진행 | 검색에 쓰는 아이디어 스냅샷 |
| 2. 특허 비교 보고서 | 자동 조사 결과의 특허 구성 대응 검토 | 특허별 구성 대응표, 원문 인용, 등록 관련 예비 신호 |
| 3. 시장성 보고서 | 자동 조사 결과의 고객·문제·대안 관련 근거 검토 | 수요·경쟁·가격·구매자·장벽, 다음 검증 계획 |
| 4. 최종 실행 검토 | 두 조사 완료 뒤 자동으로 통합 보고서 확인 | 근거와 불확실성에 연결된 다음 행동 권고 |

브랜드와 종이 기반 화면 디자인은 유지한다. 분석 중에는 회전 표시와 실제 경과 시간을 보여주고, 팝오버에서 완료된 이전 단계 결과를 다시 연다. 단계 이동은 분석을 유지하며 입력은 잠근다. 취소는 이미 전송된 네트워크 요청을 즉시 중단하지 않을 수 있으므로 비용과 처리 안내를 표시한다. 특허는 최대 8건을 비교 우선순위로 정렬하고, 인용문 안에서 검증된 verbatim 구절만 원문 팝업에서 강조한다.

## 특허·시장 검토 원칙

특허는 한 문헌에 포함된 청구항 근거를 묶어 아이디어 구성요소마다 대응 여부·공통점·차이점·미확인을 표시한다. 검색된 문헌에 유사 구성이 있다고 해서 등록 불가나 침해로 단정하지 않으며, 검색 결과가 없다고 특허 위험이 없다고 보지 않는다.

시장은 기존 다섯 차원을 유지한다. 공개 뉴스·기업 자료는 산업 또는 사업 신호로 취급하고 고객의 직접 구매·지불 의사로 격상하지 않는다. 직접 고객 검증 근거가 없으면 수요는 미검증으로 남기고, 누구를 대상으로 무엇을 확인할지 다음 검증 행동을 제안한다.

## 코드 경계

- `frontend/app.py` / `frontend/workflow.py`: 백그라운드 조사 상태와 네 단계 자동 진행, 초안 수정, 단계별 보고서.
- `src.generation.idea_parser` / `src.schemas.IdeaDraft`: 아이디어 추출, 사용자 수정 출처, AI 가설 및 미확인.
- `src.services.patent_service` / `src.generation.patent_analysis`: 문헌별 청구항 인용 및 구성요소 대조.
- `src.generation.market_analysis` / `src.retrieval.market_search`: 아이디어별 시장 질의와 고객·사업 신호 구분.
- `src.generation.business_review` / `src.pipeline`: 특허·시장 순차 진행 콜백과 다음 사업 검증 행동을 위한 근거 기반 통합 권고.
- `src.generation.executive_review`: 특허·시장 상호작용을 권고 범위, 승인 게이트, 단계별 행동으로 묶는 독립 최종 검토.
- `src.generation.report_builder`: 기존 세부 보고서 호환 렌더러와 근거 인용 유틸리티.

비용이 드는 OpenAI 실분석은 사용자가 전체 분석 시작을 눌렀을 때 실행한다. 실패 영역을 다시 조사할 때에도 API 비용이 발생할 수 있음을 버튼에 표시한다. 테스트는 외부 API를 호출하지 않고 가짜 응답과 로컬 자료로 확인한다.
