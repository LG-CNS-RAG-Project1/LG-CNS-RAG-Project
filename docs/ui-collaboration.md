# 현재 화면 기준

현재 실행 UI는 [빠른 조사 UI](quick-research-ui.md)의 4단계 구조를 따른다. 아래 내용은 이전 구성 또는 후속 확장 검토 자료이며 현재 단계·배치 설명으로 사용하지 않는다.

> 이전 기업 비교 시연에 대한 참고 문서입니다. 현재 로컬 UI의 구성과 연결 범위는 [아이디어 검토실](idea-workspace-ui.md)을 기준으로 합니다.

# 기업분석 UI·서비스 협업 가이드

## 현재 연결 범위

UI는 스마트팩토리 기업 비교를 시연한다. 기업·기술 분야·기간·질문을 기준으로
비교표와 원문 근거를 배치하며, 실제 분석 API를 호출하지 않는다.

기존 백엔드의 `StructuredIdea`와 특허·시장 모델은 이 UI 개편만으로 변경하지 않는다.
기업 비교에 필요한 UI 입력과 시연 데이터는 프런트엔드 범위에서 관리한다. 실데이터
연결 전에 공통 요청·응답을 합의하고 `docs/api_contract.md`에 기록한다.

## 담당자별 연결 조건

| 담당 영역 | 담당 내용 | UI와 합의할 항목 |
|---|---|---|
| 백엔드·통합 | 분석 요청, 실행 상태, 자료별 결과 통합 | 기업 ID, 조사 범위, 요청 ID, 부분 성공·실패, 재시도 |
| 특허 데이터·RAG | 수집, 기업 매칭, 검색, 기술 비교 | 출원인, 문헌 버전, 원문 구획, 인용 ID, 관련성·원문 확보 상태 |
| 시장·사업 조사 | 공시·시장 근거와 적용 조건 | 자료 유형, 발행일·대상 기간, 주장 성격, 연결 근거, 미확인 사유 |
| UI·시연 | 입력, 비교표, 근거 패널, 역할별 읽기 흐름 | 화면 상태, 표시 순서, 다운로드, 시연과 실데이터 구분 |

이 표는 기능별 책임을 설명한다. 팀원의 실제 배정과 파일 소유권은 팀에서 확인한다.

## 먼저 합의할 데이터

| 정보 | 필요한 필드·규칙 | 화면에서 쓰는 곳 |
|---|---|---|
| 기업 식별 | 기업 ID, 표시명, 출원인 별칭, 계열사 포함 범위 | 비교 열 제목과 근거의 기업 연결 |
| 조사 범위 | 기술 분야, 공급·도입기업 구분, 기간, 날짜 기준, 분석 기준일 | 범위 요약과 보고서 표지 |
| 비교 항목 | 동일한 행 ID, 기업별 설명, 주장 성격, 인용 ID 목록 | 사업·시장·기술 비교표 |
| 근거 | 문헌 ID·버전, 자료 유형, 제목, 원문 구절·위치, URL | 오른쪽 근거 패널 |
| 자료 시점 | 발행일, 대상 기간, 수집일, 정정 여부 | 비교 가능한 기간인지 판단 |
| 미확인 사항 | 무엇이 부족한지, 사유, 필요한 후속 자료 | 다음 조사 목록 |
| 처리 상태 | 자료별 미연결·진행·완료·없음·실패 | 부분 결과와 재시도 안내 |

`확인된 사실`, `연결 가설`, `미확인`은 색뿐 아니라 글자로 구분한다. 기업 자체 주장과
자료의 존재를 독립 검증 완료로 표시하지 않는다. 인용 ID가 실제 근거 목록에 존재하며
같은 기업·기간·문헌 버전을 가리키는지 응답 검증 단계에서 확인한다.

특허 건수나 출원 추이는 수집 범위·중복 기준이 있는 전체 집계 결과로 받는다. 검색된
일부 문헌 수를 전체 보유 특허 수로 표시하지 않는다. 근거 없는 기술력·사업성 점수는
화면을 채우기 위해 추가하지 않는다.

## 실제 API 연결 순서

1. 기업 비교 요청과 공통 비교 행·인용 구조를 합의한다.
2. 가상 데이터와 같은 표시 구조를 갖는 검증용 응답을 준비한다.
3. 프런트엔드 연결부에서 응답을 화면 데이터로 변환한다.
4. 실제 기업·문헌 ID, 링크, 원문 위치와 기간을 대조한다.
5. 자료 없음·부분 성공·실패·재시도를 확인한다.
6. 화면과 다운로드에서 시연 표시를 실제 분석 상태에 맞춰 전환한다.

백엔드가 아직 없는 상태에서는 UI 검토용 예시를 유지한다. 실데이터와 예시를 한
보고서에 섞거나, 실제 기업명에 가상 특허·시장 설명을 붙이지 않는다.

## 아이디어와 작업을 공유할 곳

| 내용 | 위치 | 적을 내용 |
|---|---|---|
| 배치·디자인 결정 | `docs/ui-design.md` | 사용자 작업, 후보, 선택 이유, 한계 |
| 화면·동작 개선 | GitHub Issue | 불편한 상황, 제안, 확인 기준 |
| 요청·응답 변경 | Issue + `docs/api_contract.md` | 예시 입력·응답과 영향받는 담당 영역 |
| 실행·시연 | `docs/ui-guide.md` | 실행 방법, 확인할 동작, 시연 범위 |
| 구현·문서 변경 | 기능 브랜치 → `develop` PR | 실제 변경, 검증 결과, 연결되지 않은 부분 |
| 참고 디자인 | 문서·자료실 | 원본 링크, 참고한 요소, 적용할 화면 |

기존 UI PR을 이어서 수정할 때는 PR 제목과 설명도 최종 화면을 기준으로 갱신한다.
팀원이 합의해야 할 API 항목은 구현 완료 항목과 구분해서 남긴다.
