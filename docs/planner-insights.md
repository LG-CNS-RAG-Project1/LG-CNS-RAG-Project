# 사업기획 근거 자료집과 시각화

스마트팩토리 신제품·신사업을 검토하는 기업 사업기획자가 뉴스 근거를 도표에서 확인하고, 기획안의 **차별 주장·공급 형태·판매 경로·가격 조건·다음 조사**를 수정하거나 정하도록 돕는다. 대표 아이디어는 SF-02(2차전지·전자부품 제조사에 기존 라인용 AI 외관 검사 장비를 공급하고 모델 유지보수 계약을 받는 사업)이다.

기존 `MarketReport`(5개 차원 판정)는 그대로 두고, 아이디어별 **근거 자료집(run)** 을 따로 만든다. 화면은 시장성 보고서 아래 '사업기획 근거 비교' 영역에서 저장된 자료집을 다시 계산(replay)해 보여준다.

## 지원하는 결정

| 결정 | 화면 | 뉴스로 답하지 못하는 부분 |
|---|---|---|
| 어떤 차별 주장을 유지·수정할까 | 구매 기준별 경쟁 주장 비교표, 비교 해석 | 당사 성능 우위, 고객의 실제 구매 기준 |
| 모듈·표준 장비·현장 맞춤 패키지 중 무엇을 공급할까 | '현장 맞춤 구성' 열, 가정 A2 | 당사 광학·현장 엔지니어링 역량(회사 입력) |
| 직접 판매와 장비사·OEM·SI 경유 중 무엇을 검토할까 | 공급 관계도, 가정 A3 | 제휴 가능성·수익 배분(회사 입력) |
| 어떤 고객·공정을 먼저 검토할까 | 외부 거래 보도·계열 적용 구분, 가정 A4 | 고객 접근성·데이터 접근(회사 입력) |
| 어떤 조건에서 가격이 성립할까 | 가격 조건 차트(사용자 입력) | 지불의사·시장가격·판매량 |
| 다음 조사에서 무엇을 확인할까 | 질문 은행 판정·중단 사유·질의 예 | — |

## 처리 흐름

```text
refresh (python -m src.services.planner_service refresh --idea-id SF-02)
  초기 수집: 프로필의 결정 영역별 질의 → NAVER 뉴스 검색 → 코드 규칙으로 선정(최대 50건)
  본문 수집: robots 확인 후 채택 기사 본문 자동 수집(reviewed_body 층, 사람 검토 아님)
  추출: 기사당 gpt-4o-mini 1회(번호 붙인 문장 → 원문 구절 후보만, strict json_schema)
  Anchor: 구절 위치 검증·표지·사전 적중 계산(원문 의존 작업은 여기서 끝)
  판정: 공급사·주장·관계·수치·반대 근거 승인 → 비교표·관계·가정·질문 판정
  후속 라운드(최대 3회×10건): 근거 공백 질문의 템플릿 질의 → 새 근거가 없으면 그 질문 중단
  게시: 새 실행 폴더(기존 실행 덮어쓰기 금지)
replay: 저장 파일만 읽어 재계산 → 의미 결과 해시 대조(검색·HTTP·LLM·Chroma 호출 0회)
review: 근거 승인·제외(사유 필수)·가격 입력 → 새 revision
reanalyze: 같은 기사로 현재 규칙 재적용 → 새 실행(규칙 변경과 자료 변화를 분리)
```

## 수집 예산

`configs/planner/SF-02.yaml`의 `budget`에서 관리한다. 고유 기사 총량은 아이디어당 80건이며 질문·차트마다 80건이 아니다. 초기 50건 + 후속 10건×3회는 연구 초기 운영안이며 최적값으로 검증되지 않았다.

- 검색 요청 40회, 요청당 20건, 질의당 2페이지, 후보 600건, 429·5xx·시간 초과만 1회 재시도
- 본문 수집 80건, LLM은 추출 기사 수 + 재시도 최대 10회(기사당 1회)
- 범위 사전은 검사 문맥 표현(비전검사·머신비전·외관검사 등)만 포함어로 쓰고, 주가·공시 나열 기사(관련주·특징주·주요공시)는 제외어로 둔다.
- 선정 제외 사유: `duplicate_url`, `before_date_from`, `out_of_scope`(범위 사전), `near_duplicate`(제목 유사 전재 후보; 대표 기사만 예산 사용)
- 배분을 채우지 못하면 `shortfall`로 남기며 무관한 기사로 채우지 않는다.
- 후속 라운드에서 같은 질의를 다시 쓰면 이어서 받은 결과부터 처리한다. 질문별 새 근거는 그 질문에 맞는 근거 종류(경쟁 질문은 주장·공급사, 경로 질문은 관계, 가격 질문은 수치, 위험 질문은 반대 근거)만 센다.
- 후속 질문 중단 사유: `answer_requirements_met`, `budget_exhausted`, `no_new_evidence_within_capped_search`, `requires_company_input`, `requires_customer_validation`, `slot_unfilled`(템플릿 슬롯을 채울 승인 엔터티 없음)

## 판정 규칙 (`planner-rules-v2`)

규칙은 명확한 패턴만 승인하고, 애매하면 사유와 함께 후보로 남긴다. 정규식·사전이 문장 의미를 모두 확정한다고 가정하지 않는다.

- **구절**: LLM이 준 구절이 해당 문장의 연속 부분 문자열이어야 한다(따옴표·가운뎃점·공백만 정규화). 없으면 `span_not_found`로 버린다. 입력에 없는 문장 번호를 단 항목은 그 항목만 버린다(`unknown_sentence_id`).
- **기업명**: 언급 구절에서 '(대표 …)' 설명을 떼고, 문장 전체가 오면 첫 주어만 이름으로 쓴다. 'A와 B'·'A·B'처럼 여러 기관을 묶은 언급과 연구진·교수 언급은 기업으로 쓰지 않는다.
- **공급사**: 제목 첫머리(`이름,`), 주어 조사 + 공급 동사(출시·공급·개발·탑재·구현·수행 등), `이름 대표`(인터뷰) 중 하나와 제공물 표현이 있어야 한다. 주어 + 도입 동사(도입 기업 패턴)·공공·연구기관·부정·철수 문장은 승인하지 않는다.
- **주장**: 주체가 그 기사의 승인 공급사여야 한다(이름이 없으면 기사의 승인 공급사가 하나일 때만).
- **관계**: 관계 동사가 있어야 간선이 된다(동시 언급은 간선 없음). 철수 > 계획·협약 > 추가 발주 > 운영 > 설치 > 계약 > 실증 > 공동 개발 > 공급 순으로 유형을 정한다. 자회사·계열·현지 법인 표지는 계열 적용으로 표시해 외부 거래에서 뺀다. 익명 도입처는 전재 묶음별로 따로 둔다.
- **셀 상태**: 승인 근거만 쓴다. 상충(같은 행·기준에 명시 긍정과 명시 부정) > 명시 > 설명 불완전(약한 표현만·제목만·잘린 끝 문장·예정) > 미확인. 적용 산업 범위가 다른 긍정·부정은 상충 대신 '조건 상이' 표시.
- **미확인 사유**: 주체 미확정 후보 → 추출 실패 → 미추출 → 잘린 요약·본문 미확보 → 본문에서도 찾지 못함 → 자료집에서 후보 없음. 미확인은 기능 부재나 0이 아니다.
- **해석 문장**: 고정 템플릿. 당사 차별점 입력이 기준을 명시하고 다른 공급사도 그 대응을 명시하면 "단독 차별점 확정이 어려울 수 있음 → C4(총 작업량 비교)"를 제시한다. 입력이 관련 표현만 담으면(예: '기존 라인') 차별점 판단 대신 "공급 범위·현장 작업 책임 정의 → E2·C4"를 제시한다. 경쟁력 점수·성능 순위·성공 확률은 만들지 않는다.
- **가격 점도표**: 판매 단위·포함 범위 표현이 같아도 자동 판정만으로는 비교 가능으로 보지 않는다. 검토자가 승인한 같은 조건의 가격 근거가 2건 이상일 때만 표시 가능으로 바꾼다.
- **질문 판정**: 질문 은행 `required_fields`를 프로필 `question_checks`의 코드 검사로 판정한다. 회사 내부 조건(M4·G4·E3·E4·R4)은 회사 입력, C4는 고객 확인으로 넘긴다. 정렬은 결정 연결 가정의 상충·반대 → 근거 공백 → 답변 가능성 → 질의 가능 여부 → 질문 순서다.

## 가격 조건 (`src/planner/pricing.py`)

초기 구축 프로젝트 1건, 만원 단위. `Pmin = C/(1-m)`, `Pmax = B×T/12 - I`. 하한은 1만원 단위 올림, 상한은 내림해 교집합을 표시한다(단일점 허용). Decimal을 문자열로 저장하며 실수 계산을 쓰지 않는다. 값이 하나라도 없으면 계산을 보류하고, `m`은 0 이상 1 미만, `C>0`, `I≥0`, `T>0`이어야 한다. `Pmax≤0`은 "양수 판매가 불성립"으로 표시한다. 예시 모드(C=4000, m=30%, B=3600, I=1000, T=24 → 5,715~6,200만원)는 저장하지 않고 상시 표시한다. 지불의사·시장가격·판매량·사업 성공의 근거가 아니며 구독형 현금흐름은 포함하지 않는다.

## 재현성

- 같은 기사·Anchor·추출 결과·검토/입력·프로필·질문 은행·기준일이면 같은 의미 결과(정렬·Decimal 문자열 고정 JSON의 SHA-256)가 나온다. 실행은 프로필·질문 은행 사본을 함께 저장하므로 설정 파일을 바꿔도 이전 실행의 replay는 변하지 않는다(현재 규칙과 다르면 표시만 한다).
- LLM `temperature=0`만으로 재현되지 않으므로 replay는 저장된 추출 결과를 읽는다. 의미 결과의 동일성은 그림 픽셀 동일성과 별개다.
- 본문(`bodies/`)과 원응답(`raw_responses/`)은 지워도 replay가 된다. 실행 폴더(`data/market/runs/`)는 기사 본문을 담으므로 Git에 커밋하지 않는다.

## 화면 (`frontend/planner_view.py`)

경쟁 주장 비교 · 공급 관계·다음 확인 · 가격 조건 · 자료집·재현 4개 탭. 비교표 칸을 누르거나 목록(키보드 조작 가능)에서 고르면 그 칸의 근거 구절·자료 층·출처 링크·적용 범위·다음 질문만 보인다. 공급 관계도는 확정 관계만 그리고 후보는 표로 분리한다. 자료집·재현 탭은 건수·제외 사유·본문/추출 상태·해시 일치·이전 실행 대비 변화와 같은 근거의 텍스트 보고서를 제공한다. 새 자료집 만들기는 `IDEALENS_PLANNER_REFRESH=1`과 OpenAI·NAVER 키가 있는 로컬 실행에서만 보인다. 배포 환경(SCC)은 실행 폴더가 유지되지 않아 저장된 자료집이 없으면 빈 상태를 보인다.

## 한계와 미검증

- 자동 의미 판정의 정확도는 정답셋이 없어 측정하지 않았다. 연구 큐레이션 예시는 정답 데이터가 아니다.
- 공정·검사 대상·결함은 아직 추출 규칙이 없어 고객·공정 후보 비교표는 표시하지 않는다.
- 사건 동일성은 확인하지 않는다(관계 보도는 전재 묶음 기준으로 센다). 같은 사례 진행 이력도는 같은 공급사·실명 고객의 서로 다른 단계 사건에 사건일이 모두 있을 때만 켠다.
- 매체별 본문 추출 품질과 이용 약관은 매체마다 다르다. robots 허용은 이용 허락과 같지 않다.
- 분야 프로필은 SF-02만 정의했다. 다른 분야는 기준 사전·반례를 따로 검증해야 한다.

## 기업 효용 평가 설계 (미실시)

같은 자료집에서 만든 **텍스트 보고서**(`report_text.semantic_to_markdown`, 자료집·재현 탭에서 내려받기)와 **시각화 화면**을 같은 근거 조건으로 비교한다.

1. 참가자: 실제 사업기획 담당자 5~8명(문제 발견용 형성 평가, 통계적 일반화 목적 아님). 아이디어·순서를 교차 배정한다.
2. 과업: ① 수정할 차별 주장 찾기 ② 검증되지 않은 거래(계열 적용·계획·익명)를 분리하기 ③ 두 공급 방식·판매 경로 중 선택을 바꿀 조건 쓰기 ④ 가격 조건이 깨지는 이유와 다음에 확보할 값 찾기
3. 측정: 정답·근거 적합성(근거를 가린 평가자가 판정), 과도한 결론 수, 출처 확인 시간, 추가 조사 질문의 구체성, 추가 조사 부담. 만족도·선호도만으로 효용을 판단하지 않는다.
4. 통과 조건: 핵심 주장에 잘못된 출처·역할·수치가 없고, 근거 적합성을 유지하면서 확인·작성 부담이 줄어야 한다. 개선 폭 목표는 기준선을 측정한 뒤 정한다.
