# 스마트팩토리 기업분석 UI 디자인

## 선택한 방향

**기업 비교표를 중심에 두고, 선택한 내용의 근거를 오른쪽에서 확인하는 작업 화면**을
기본으로 삼는다. 목적은 기업의 사업 방향·시장 관련성·기술 접근을 같은 기준으로
비교하고, 판단에 사용한 문헌과 미확인 사항을 놓치지 않게 하는 것이다.

이 디자인은 실제 자료 연결 전에도 배치와 사용 흐름을 검토할 수 있는 시연이다.
가상 A사·B사와 문헌을 사용하며, 산업 전체 분석이나 기업 기술력 평가가 구현됐다는
뜻은 아니다. 설비 관리 예시는 시연 시나리오이며 서비스의 전체 기술 범위를 한정하지 않는다.

## 검토한 후보

| 후보 | 중심 경험 | 장점 | 선택 판단 |
|---|---|---|---|
| 비교 작업 화면 | 범위 → 기업 비교 → 선택한 근거 | 같은 항목의 차이와 원문을 왕복하기 쉬움 | 기본 화면으로 선택 |
| 보고서 중심 화면 | 핵심 요약 → 상세 서술 → 각주 | 발표·공유·경영진 읽기에 적합 | 요약과 다운로드에 반영 |
| 대화 중심 화면 | 질문 → 답변 → 후속 질문 | 질문을 자연스럽게 구체화할 수 있음 | 후속 기능 후보; 비교 기준·범위를 따로 유지해야 함 |

기본 화면에는 첫 번째 후보를 적용한다. 경영진 요약은 보고서 중심 후보의 읽는 순서를
활용하고, R&D 상세는 기술 구성과 출처를 더 직접적으로 보여준다.

## 화면 배치

| 영역 | 배치할 정보 | 이유 |
|---|---|---|
| 왼쪽 | 분석 범위와 예시 선택 | 기업·기술·기간의 맥락을 유지 |
| 상단 | 분석 질문, 적용한 범위, 시연·처리 상태 | 무엇을 비교하는 결과인지 먼저 확인 |
| 가운데 | 기업별 비교, 경영진·R&D 관점 | 동일 항목을 나란히 읽고 차이를 파악 |
| 오른쪽 | 선택한 인용의 문헌 정보·원문·위치 | 비교 내용을 잃지 않고 근거 확인 |
| 결과 아래 | 미확인 사항, 다음 조사, 보고서 | 부족한 근거를 후속 작업으로 연결 |

좁은 화면에서는 비교 내용 다음에 근거 패널을 배치한다. 긴 기업명·문헌 제목이
줄바꿈되도록 하고, 문서 전체를 작은 글자로 압축하지 않는다.

## 시각 디자인

- 밝은 중립 배경, 흰색 작업 영역, 청록색 강조를 사용한다. 강조색은 선택과 주요 행동에 집중한다.
- 제목·비교 내용·출처 정보의 크기와 간격을 구분한다. 장식보다 기업 간 비교의 정렬을 우선한다.
- 경영진·R&D 전환은 결과 가까이에 둔다. 다른 페이지로 이동한 듯한 맥락 변화는 줄인다.
- 문헌 제목, 자료 유형, 원문 구획과 날짜는 일정한 순서로 표시한다.
- 사실·가설·미확인은 글자로 구분한다. 출처 유무와 확인 수준을 색만으로 표현하지 않는다.
- 실제 협력 관계가 없는 기업·기관을 파트너처럼 배치하지 않는다. 분석 대상과 자료 출처는 해당 명칭으로 표시한다.

## 참고한 디자인

[찐망고 파트너 로고 모음](https://ref.jjinmango.kr/c/partner_logo)과
[서비스 소개 모음](https://ref.jjinmango.kr/c/feature)의 캡처를 참고했다.
타사 디자인의 이미지·로고를 서비스에 복제하지 않고 배치 원리를 적용한다.

| 살펴본 사례 | 화면에서 관찰한 요소 | 적용할 원리 |
|---|---|---|
| dcamp 파트너 로고 | 로고를 같은 크기의 구획에 정렬 | 기업 표시와 출처 영역의 시각적 높이를 일정하게 유지 |
| 디펙트럼(Dpectrum) 서비스 소개 | 번호가 붙은 단계, 짧은 제목, 구분된 행 | 조사 흐름과 다음 작업을 짧고 순서 있게 설명 |
| 네이버웍스 서비스 소개 | 넉넉한 여백, 두 영역 구분, 큰 제목 | 비교 결과와 근거의 위계를 명확하게 분리 |

위 관찰은 공개 캡처의 시각 구성에 관한 것이다. 해당 서비스의 내부 구현이나 실제
기능을 검증한 결과가 아니다. 파트너 로고 패턴은 서비스 분석 화면의 핵심 요소가
아니므로, 로고 장식보다 비교표·인용·상태 표시를 우선한다.

## 유지할 정보 원칙

1. 가상 기업·문헌은 화면과 다운로드에서 시연용임을 표시한다.
2. 실제 기업명을 입력해도 가상 기업의 설명을 그 기업에 귀속하지 않는다.
3. 분석 요청의 범위와 표시 중인 결과의 범위를 구분한다.
4. 자료가 없거나 수집되지 않은 경우 기업의 기술이 없다고 결론내리지 않는다.
5. 특허의 기술 내용과 실제 제품 적용·매출·고객 실적을 구분한다.
6. 시장·사업·특허의 연결은 근거가 있으면 사실로, 추론이면 가설로 표시한다.

## 다음 구현에서 이어갈 부분

기업 ID, 문헌 버전·원문 위치, 자료별 시점과 상태를 API에 연결한다. 실데이터로
비교표와 근거 패널을 검증한 뒤 저장된 분석·후속 질문·보고서 형식을 확장한다.
화면의 신뢰도나 성과를 표현할 때는 사용자 평가와 실제 측정 결과를 사용한다.
